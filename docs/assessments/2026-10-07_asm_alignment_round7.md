## Folded after this round

- **Presence (Thor, Odin, Enlil, Enki, Asar, Pangu, Sofia, …)** — `onBroadcastPresence` only updates the count; `markBroadcastHealthy()` is called only inside `applyPushedStatus` after the backend confirms (gate counts every call).
- **Dropped pushes (Enki, Asar, Pangu, Odin)** — a push inside the 1 s window is no longer dropped: it leaves one trailing backend re-read; a failed re-read clears the healthy flag so the poll resumes; the first read of a push is spread over 0–1.5 s. The read burst is recorded as HP-34 (CODE + INFRA).
- **Production auth (Odin)** — `GET /sessions/{id}` required a login, so with Auth0 configured every anonymous participant's status reads would 401 (swallowed). It is now public, exactly like `GET /sessions/code/{short_code}` (same SessionRead). Gate `tests/cube1/test_public_session_read.py`.
- **Cycle scoping (Enlil, Thoth)** — the governance override writes into the current cycle; the Cube 7 metrics engine reads one cycle; `/rankings/scale-info` counts the cycle it resolved.
- **SIM parity (Krishna, Athena)** — the SIM theme store is keyed by session + cycle: an un-themed re-opened round has empty /themes, theming pending, and refuses a ballot, as LIVE.
- **Runtime proof (Athena)** — `tests/live_db/test_reopen_cycle.py`: two full rounds on a real database (theme → vote → aggregate → re-open → theme → vote → aggregate), then the ballot, the ballot check, GET /rankings, the override write + audit, the Cube 9 analytics winner and ballot count, and the report summary all speak about cycle 2 only.
- **Found while building that proof** — every themes_ready broadcast's own log call raised (`event=` collides with structlog's first argument), so the pipeline's handler swallowed it and skipped the themes_ready webhook after it. Fixed in `app/core/supabase_broadcast.py` (4 calls); AST gate `tests/core/test_log_event_keyword.py` scans every logger call in app/.
