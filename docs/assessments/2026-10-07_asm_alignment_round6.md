## Folded after this round

**Class 1 — a status not from the backend reaching a participant (Thor, Aset, Sofia).** Every status input now goes through one rule: page load and poll (round 5) and now both push handlers. A Broadcast or postgres_changes status is only a hint: against the real backend it triggers a backend re-read (one at a time, ≤1/s) whose answer is applied through `statusAdvances`; the channel is marked healthy only when the backend confirms the pushed status, so forged traffic can no longer suppress the corrective poll. Without a backend the push applies only if it advances, cycle first. The moderator's status broadcast carries `current_cycle`. HP-32 is corrected (it overstated round 5) and HP-33 records the channel-level fix (private channels + Realtime auth, no anon writes to session_status — INFRA + APPROVAL).

**Class 2 — reads not scoped to the cycle (Enki, Christo, Thoth).** The ballot is exactly the current cycle: no fallback to the previous cycle, so a re-opened round neither freezes on nor takes ballots for old themes while its own theming runs (the client keeps waiting; a ballot is refused). Cube 7's verify / anomalies / readiness / scale-info / emerging / personal / overrides reads default to the current cycle via `_resolve_cycle`. Cube 9's analytics winner and ballot count, and the report's ranking summary, read one cycle (the newest aggregated one) — the winner query no longer raises on a re-opened session.

Gates: ballot-themes 36, status-advance 10; `tests/cube7/test_ballot_cycle.py` (real Postgres) updated to the strict rule (an un-themed re-opened round has no ballot and refuses one); backend 3426 passed.
