# API audit — "Ensure all apis for eXeL AI polling work properly" (2026-10-07)

Ask persisted verbatim: `docs/asks/2026.10.07_*_all_apis_work.md` (commit 121dc17).

## How it was tested (not mocked)

| Surface | Method | Result before | Result after |
|---|---|---|---|
| FastAPI backend, all 158 operations | Every operation called against a real PostgreSQL 16 (schema from the models), app lifespan running, auth as a moderator | **14 × 500** | **0 × 500**, 0 tracebacks, 0 failed background tasks |
| FastAPI end-to-end journey | create → question → open → QR → 6 joins → poll → 6 submissions → time tracking (Auth0 ids) → list → presence → rank → theming → re-run → 6 ballots → re-run refused → Borda aggregate → CSV → close → destroy | stopped at the first 500 | **38 / 38** |
| Backend unit suite | `pytest` | 3316 passed | **3329 passed** (+1 test updated, +12 gates), 66 skipped (need live AI/Supabase keys) |
| Cloudflare worker `/api/*` | `worker.js` driven with a Worker-shaped env (in-memory `caches.default`, SPA-fallback ASSETS) | 4 of 8 routes the app calls answered `index.html` | **all 8 answer from the worker**; Path C round-trip stores and returns |

The 4xx answers left in the sweep were read one by one. All are correct refusals: validation, or the state
machine refusing actions on a session the sweep had already archived.

## What was broken, and the class each fix closes

1. **Router ↔ service signatures (cube 10).** `POST /submissions`, `POST /challenges`, `/challenges/{id}/claim` and
   `/submit` never passed `db`, so every call raised `TypeError`. Each now takes `db` and turns a `ValueError` into a 400.
2. **Stdlib loggers given keyword fields (16 modules).** `logger.info("…", session_id=…)` on a `logging.Logger` raises
   `TypeError`. Among the paths that crashed were `/ai/run`, the live per-response summarizer, AI provider failover,
   CQS scoring and the Supabase broadcast. These modules now use `structlog.get_logger`, which the project already
   configures and which handles both call styles.
3. **Names never imported.** `aggregate_rankings` / `identify_top_theme2` in cube 7 made `POST /rankings/aggregate`
   always 500. `Session` was missing in cube 5, so the on-chain record step silently never ran.
4. **Naive TIMESTAMP columns.** `trend_snapshots.snapshot_at`, `trend_subscriptions.current_period_end`,
   `usage_records.occurred_at` and `webhook_subscriptions.last_delivery_at` / `last_failure_at` were naive while every
   write is timezone-aware. That broke trend snapshots, and broke CSV export through its usage meter. The models now
   match the Supabase migrations, which already declare `timestamptz`.
5. **Auth0 user id parsed as a UUID.** `POST /desired-outcome` and `POST /time/start` called `uuid.UUID("auth0|…")`.
   The new `resolve_participant_id()` finds the caller's real `participants` row in the session. Time tracking with
   no row is a 404 ("Join the session before tracking time"), never a foreign-key 500.
6. **Data destruction named a column that does not exist** (`ResponseSummary.original_text`), so nothing was ever
   destroyed. It now also destroys the two other copies of a participant's words: text responses (scrubbed + clean)
   and voice transcripts.
7. **Stripe webhook.** An unsigned event was accepted whenever the webhook secret was unset, in production too.
   That meant a forged "payment completed" would be honoured. It is now refused with 503 in production. Bad JSON
   is a 400, not a 500.
8. **External providers.** No AI key in production gives a 503 "AI provider not configured". An unreachable Stripe
   gives a 502. CQS scoring now degrades to the offline provider outside production, as theming already did.
9. **Post-polling orchestration reused the request's DB session.** The response closed that session mid-flush, so
   theming after `rank` died in the background. It now opens its own session, as cube 5's pipeline runner already
   does, and the task is held so the event loop cannot drop it.
10. **AI theming re-run appended a second full set** (57 → 114 themes for 6 responses), despite the docstring calling
    it idempotent, and the ballot then had to rank both. A re-run now replaces the cycle's themes. Once ballots
    exist it is refused with 409, so cast votes can never be orphaned.
11. **Duplicate OpenAPI operationId** `get_presence` (cube 1 and cube 4): the cube 4 handler is now `get_collector_presence`.

### Live site (Cloudflare worker)

12. **Four Pages Functions never ran.** This deploy is Workers Static Assets, so `functions/` is never executed.
    These routes therefore answered `index.html` with a 200:
    - `/api/responses`: Trinity **Path C / Channel C**
    - `/api/sessions`
    - `/api/drone-link`
    - `/api/geo`

    Same class as the earlier `/api/donate` fix. They are now dispatched from `worker.js` (`PAGES_ROUTES`) using the
    same function files, with no rewrite. The SACRED Trinity files (`dashboard/page.tsx`, `session-view.tsx`,
    `mock-data.ts`) are untouched; Path C's sender was already correct and simply had nothing answering it.
13. **Navbar "Scan QR"** fetched `/api/v1/sessions/qr-generate`, a route that exists nowhere. It opened the site's
    own HTML as a "QR". It now treats only an image as a QR, and otherwise uses its existing fallback.

## Gates (each fails if its class returns; 11 of 12 proven red on the pre-fix code)

- `backend/tests/test_api_contract_gates.py`: router calls bind; no stdlib-logger kwargs; every DateTime column tz-aware;
  unique operationIds; no `UUID(user.user_id)`; destroy names only real columns and touches every copy; Stripe
  production refusal and bad-JSON 400; no `create_task(fn(db, …))`; theme storage replaces the cycle.
- `frontend/tests/worker-api-routes.test.mjs` (in `test:ci`): finds every `/api/<name>` the app calls and fails if the
  worker answers any of them with the SPA fallback; Path C POST → GET round-trip; `/api/geo` JSON + 405.

## What this does not prove (stated, not assumed)

- **No FastAPI backend is hosted for the live site.** Its build has no `NEXT_PUBLIC_API_URL`, and the app runs in mock
  mode against Supabase plus the worker. Fixes 1–11 make the API/SDK product correct for whoever deploys it. They do
  not change what the phone sees today. Fixes 12–13 do.
- Cross-device Path C on the live site still uses the Cloudflare Cache API, which is per-datacenter, until a KV
  namespace is bound as `RESPONSES` in `wrangler.jsonc`. That binding is operator infrastructure.
- Live AI providers, Stripe and Supabase were not reachable from the sandbox. Their paths were tested to the
  provider boundary (offline provider, 502/503 mapping).
