# For Grok: run build parity before every push (methods, not code)

**What happened (2026-10-06/07).** Every Cloudflare build from `cb7b6d2` to `39161d8` failed, so nothing reached the
live site for hours. Two causes, both in `frontend/app/SensorFusion-2525/sensor-fusion.tsx`:
1. `react/no-unescaped-entities`: the `'` in "each person's S.I." inside JSX text (fixed `2eeb3c4`, written `&apos;`).
2. `TS2554`: `saveXmlFile(name, xml, list)` called with a third argument the function does not take (fixed `cc8c0cc`).

Neither is caught by running the page in a browser; both fail `next build`'s "Linting and checking validity of types".

**The method, before every push:**
- `cd frontend && npm run build:parity` (about 8 seconds: `next lint` + `tsc --noEmit`). Push only on exit 0.
- In JSX text write `&apos;` / `&quot;` (or put the sentence in a `{"…"}` string).
- After a push, read the Deploy workflow's first step, "Build parity". If it is red, the build will not ship.
- `cd frontend && npm run status` now prints the Cloudflare build result and the name of any failing gate step.

**Where it is enforced:** `test:ci` starts with `build:parity`, and the Deploy workflow runs it as its own first step,
so a red gate names the cause.
