## four faults the cut met on its own first boots — kept as the class

1. The lawn's constants were first `var`s at the end of script #1. `toolSelfTest()` runs synchronously above that
   zone, so when the scenario-picker row entered the Capital they were still `undefined` and the whole self-test threw
   (`QA_THREW · Cannot read properties of undefined (reading 'x')`). The r.208 rule, met again: every new definition
   is a hoisted function. They are.
2. The first `capIntroTick` waited for a track that was `up` with `lifePct 0`; the fire path lowers `up` itself on a
   kill, so `CTIME` was never written (`CTIME MISSING · run run`). The tick now completes the fall whether or not the
   fire path lowered the track.
3. The six rows first ran at 1800/1900 ms — after the deck's own `ASM_MARKED_BY_THE_LOOP` row had exposed its one
   plate at 1900 ms — and their `rangeReset()` re-stood every plate under it, so the loop marked the nearest plate
   instead of the exposed one at all four viewports. The rows now run at 1750/1760 ms, before that row's setup.

4. `CTIME` counted hits by row time (`t ≥ t0`); a row's `t` is stored to two decimals and at one viewport rounded
   below the clock it was born on, so the harness read `hits 0` against one `HIT` row at 844×390. The lawn's run
   now counts from the row INDEX at START, never from `t`.
