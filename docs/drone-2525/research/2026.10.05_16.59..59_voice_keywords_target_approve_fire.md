# Voice keywords for Drone-2525 — TARGET · APPROVE · FIRE (+ T1…T9)

Asks: Addenda 18–19 (round folder ASK.md). Research only; nothing built. Voice is always a REQUEST — "fire" fires only a red box.

## What exists off the shelf (checked 2026-10-05)

| Option | On device | Size | Has our words? | Per-voice tuning | Notes |
|---|---|---|---|---|---|
| Web Speech API (`SpeechRecognition`) — already in the deck (r.042 grammar) | Chrome 139+: `processLocally=true` after a one-time language pack; otherwise server | 0 in the page | any English word | none | No Firefox; iOS Safari server-side; phrase biasing "planned", not shipped |
| TF.js speech-commands `BROWSER_FFT` + transfer learning | yes | base 5.87 MB (measured, float32, 2 shards) + a tiny head | base has one…nine, stop, go — NOT target/approve/fire | YES — the documented API trains a new head from a few clips per word, in the browser | Google's own path; exports to TFLite (their conversion notebook) |
| openWakeWord (ONNX / TFLite) | yes | ~0.7–2 MB per word | train your own (TTS clips + negatives) | retrain offline | Built for wake words; 3 words = 3 models |
| onnx-wakeword | yes | ~74 KB INT8 / 128 KB FP32 per model | train your own | retrain | Smallest found; Web runtime included |
| Vosk-browser (Kaldi WASM) with a closed grammar | yes | small English model tens of MB | any word in the grammar | no | Too big for the 7.77 MB deck |
| Picovoice Porcupine / Rhino (WASM) | yes | small | custom keyword from text, no recording | no | Proprietary; free tier 3 active users/month — not for an open game |

None of the small models ship with TARGET / APPROVE / FIRE; every on-device option means training a small head for our words.

## Recommendation (two layers, one interface — the Sensor Fusion pattern: one model file, browser runtime, swap without changing callers)

1. **Now, zero size:** keep Web Speech as the default, request `processLocally` where the browser offers it, and match ONLY our grammar
   (`target`, `approve N`, `fire N`, `reload`, `one…nine`) — anything else is ignored.
2. **On-device keyword model (the "TFLite-like" file):** TF.js speech-commands with a transfer head for 13 classes — TARGET, APPROVE, FIRE, RELOAD,
   ONE…NINE (the base already knows one…nine), _noise_, _unknown_. The head is kilobytes; the base (5.87 MB) loads from the CDN the first time and is
   cached — it is not inlined into the 7.77 MB deck. Smaller still later: distil to onnx-wakeword-class models (~74–128 KB each) once the words are fixed.
3. **VOICE CALIBRATION (Settings → Voice):** say each word 8× (and 20 s of room noise); the page trains the head on the device, shows a per-word
   confidence and a confusion check ("FIRE heard as FIVE?"), saves the head in the browser (never uploaded), and has RESET. The game uses the trained
   head when present, else Web Speech.

## Safety (unchanged doctrine)
Voice "approve 3" approves T3 like the button; "fire 3" turns onto T3 and fires only if it is red; a low-confidence word is shown, never acted on.
