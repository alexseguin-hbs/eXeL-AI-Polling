## 1. THE ONE SHARED SHADER

**Problem (confirmed):** the "solid faces" shader is hand-copied in three files, never shared. Canonical source is `mission-planning.tsx` — `FACE_SHADE` kind→factor record (`:444`), `darkerHex(hex,f)` channel-multiply (`:422-428`), and `radarSolidFaces()` project→cull-by-refusal→mean-depth→painter-sort (`:449-488`), rendered as opaque polygons at `:3646-3652`. Copy #2 is `room-designer.tsx:47-56` (`FACE_SHADE {top,front,side}` + `shade()`) driving `voxel3D` (`:628-713`). Copy #3 is the walkthrough's inline `shade()` (`architect-walkthrough.tsx:25-29`) with hardcoded wall factors `shade(C.wall,0.95)` far / `0.7` sides (`:73-77`), painter sort `b.depth-a.depth` (`:80`). The three copies even **disagree on depth-sort sign** (mission-planning `a.depth-b.depth`, walkthrough `b.depth-a.depth`).

**Extract one pure module — `frontend/lib/solid-shade.ts`** (OUTSIDE `wire-core`, because `wire-core/vector-law.ts:4-15` says "Shading is forbidden" and `wire-model.ts:7` says "no faces"; the solid shader is presentation, not model). Follow the precedent of `scene-project.ts:26-47` (pure, cull-by-refusal, header documents the port from `radarSolidFaces`). Exports:

- **`shade(hex, f)`** — the single hex-channel-multiply. Replaces `darkerHex` (`mission-planning.tsx:422-428`), `shade` (`room-designer.tsx:50-56`), and the inline `shade` (`architect-walkthrough.tsx:25-29`). One 6-line function, three deletions.
- **`FACE_SHADE`** — canonical orientation→factor map keyed by world-normal class: `{ top:1.0, up:1.0, front:0.82, side:0.6, floor:0.9, ceil:0.52 }` (brightest up, darker sides, matching the radar's `{base:1.0, wall1:0.84, wall2:0.7, cos:0.52}` feel). Walls stop using ad-hoc `0.95`/`0.7`.
- **`solidFaces(quads, project)`** — generalized `radarSolidFaces`. Takes tagged quads `{pts:Vec3[], kind}` and a **passed-in projector** (so each surface keeps its own camera); projects each vertex; **REFUSES (drops) any face with a behind/non-finite vertex** exactly like `push()` at `:469-473`; computes per-face mean depth; returns **painter-sorted on ONE fixed convention** (resolve the sign mismatch here — pick far→near once, document it).
- **`boxFaces(originCorner, w, d, h, rot)`** — emits a cuboid's quads tagged by world normal, with **back-face cull** (not the fixed 3-face octant that `voxel3D`'s `iso()` hardcodes at `:633-637`/`:705-707`, which fails under free-look). This is what lets furniture AND walls feed the same call.

**Walkthrough wiring:**
- (A) Build the 6 wall/floor/ceiling quads through `solidFaces()` + `shade()` + `FACE_SHADE`, replacing `addQuad`'s manual fills and the inline shade (`architect-walkthrough.tsx:73-80`).
- (B) **Add furniture (the operator's core ask).** Iterate `room.objects ?? defaultObjectsForRoom(room.k)` — the SAME source the 2D plan and `voxel3D` use (`room-designer.tsx:81`). For each `PlacedObject`, reuse the box math from `room-objects.ts` (`footprintOf` `:337-341`, `heightOf` `:78-82`, `elevOf` `:372-375`, `shapePartsOf` `:424-445`, `OBJECT_SPEC[kind].color` `:88`) via `boxFaces`, projected through the **walkthrough's own pinhole `project()`** (`:53-61`, kept — see §2).
- (C) Push **every face — walls + furniture — into ONE `faces[]` array, painter-sorted ONCE**, so a sofa correctly occludes/is occluded by a wall and both shade identically. This is the literal realization of "objects and walls mimic the radar shading via the same function."

`solid-shade.ts` becomes the canonical geometry→opaque-faces seam behind the radar dome, the voxel, and the walkthrough, and the stable face/box description the export pipeline can read (§3).

**KEEP BESPOKE (legitimate, documented divergence):**

**R-CORE ledger wiring:** the walkthrough currently touches neither R-CORE meaning (the interaction reducer `rcore-gestures` nor the memory ledger `canonical/rcore.ts`). ## 3. REVIT-INPUT BASIS

The canonical `ArchitectProject` `SpaceEntity` (µm, ENU) is already the Revit-input seam, and `wire-model.ts:1-6` already declares the one-model→`.py/.obj/.cs/.cpp` export doctrine. The gap is that the walkthrough's geometry never *enters* a WireModel (`scripts/wire-export` referenced at `wire-model.ts:3-5` never sees it). Minimal canonical changes to make this a clean Revit basis **without breaking the "no wall mesh in the adapter" rule** (walls stay edge-only in `wire-core`; faces live only in the `solid-shade` overlay):

- **`SpaceEntity.shape RECT→POLY`.** Generalize the footprint from axis-aligned rectangle to polygon so non-rectangular rooms round-trip. Keep RECT as a POLY special-case so existing seeds (`buildProjectFromSeed`) and `$240k/$67k/$231.5k` cost math are untouched.
- **Openings as first-class.** Add `openings[]` on walls (door/window: sill, head, width, host-wall ref) so `openingOnWall` (`primitives.ts:60-77`) is driven by canonical data, not the `RoomCell` adjacency heuristic (`architect-walkthrough.tsx` `nb.N/E/W`). Revit's native objects are walls + hosted openings; this is the closest-to-Revit shape.
- **Levels.** Add an explicit `levels[]` (name, elevation) and host spaces to a level, replacing the implicit single-storey `CEIL_FT=10`. Revit is level-centric; a flat basis maps 1:1 to Revit `Level`.
- **Materials.** Promote the per-object/per-surface color (`OBJECT_SPEC[kind].color`) into a small `materials[]` table referenced by id, so `shade()`/`FACE_SHADE` read a material, not a literal. Revit materials and the Unreal/Unity material slots both bind here.

**The ExportManifest seam.** Define one `ExportManifest` emitted from the WireModel + canonical twin: `{ walls(edges+openings), spaces(POLY footprints), levels, materials, objects(box specs: footprint/height/elev/rot/kind), units:µm, hash:canonicalHash }`. gltf / revit / unity / unreal all hang off THIS manifest as sibling writers under `scripts/wire-export` — `wire-model.ts:1-6`'s `.obj`(gltf-adjacent)/`.py`(Revit/Dynamo)/`.cs`(Unity)/`.cpp`(Unreal). The adapter stays mesh-free: it emits edges + box specs + the manifest; meshing/lighting is each engine's job downstream. `canonicalHash` on the manifest is the determinism proof that the Revit import equals what the operator saw.

## 4. PROGRESSIVE UNLOCK PATH

One model, progressively richer readers. Each tier reads the **ExportManifest** (§3), never a re-authored copy.

The unlock is additive detail, never a re-model: `RECT→POLY`, openings, levels, materials (§3) are exactly the fields each higher tier needs, so an operator "unlocking Revit" enriches the same twin the walkthrough already rendered.
