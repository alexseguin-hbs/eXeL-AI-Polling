# Red first — DD-98 · the dot nomenclature comes off the Cube tiles

**His words (operator, 2026-10-18, on the live Settings → Cube Architecture screen):**

> when lookin at Cube 1-9 on settings I never asked for dot nomenclature; remove.

**Invariant:** *no cube tile carries a decorative per-cube dot pattern; the completion segments, the status
dot, the number, the name and the description stay exactly as they are.*

## What was there

`frontend/components/cube-status.tsx:129-139` rendered a 3×3 grid of 3 px squares on every tile, fed by
`cubeFingerprint()` in `frontend/lib/voxel-fingerprint.ts` — a seeded FNV-1a bit pattern. That helper's own
header credited the pattern to *"the operator's 'unique visual'"*. It was not his. The attribution was mine,
and it is the second of its kind found in one hour (the first: `8×8×8 for 10×10×10` in `cube-dev-sim.tsx`,
traced by `git log -S` to commit `06f2a2251`).

Nothing in the repository measured the dots. `tests/cube-grid.test.mjs` reads `cube-status.tsx` and pinned
only the grid order and the cube names, so nine tiles could carry an unasked-for visual with every gate green.

## The gate, RED on the pre-change bytes

Three assertions added to `frontend/tests/cube-grid.test.mjs`, run before any source change:

```
FAIL: no per-cube dot grid is rendered on the Cube tiles
FAIL: cube-status.tsx does not import or call cubeFingerprint()
cube-grid: 19 passed, 2 failed
```

The third assertion — `progressSegments(cube.completion, 4)` still present — was **green before and after**
on purpose: it is the guard against tidying away the four completion bars he did not ask to lose (release
rule 6), not a claim about the dots.

## GREEN after

```
cube-grid: 21 passed, 0 failed
```

## What changed

| file | change |
|---|---|
| `frontend/components/cube-status.tsx` | the fingerprint `<div>` deleted; `cubeFingerprint` dropped from the `:7` import, `progressSegments` kept |
| `frontend/lib/voxel-fingerprint.ts` | `cubeFingerprint()` retired; header rewritten to say the attribution was mine, not his; `progressSegments()` unchanged |
| `frontend/tests/voxel-fingerprint.test.mjs` | retired (34 lines) — with no consumer it only proved the function matched itself |
| `frontend/package.json` | `test:voxel-fingerprint` removed from the scripts and from `test:all` |
| `frontend/tests/cube-grid.test.mjs` | the three assertions above |

## Why the helper is retired rather than kept

`cubeFingerprint` had exactly two consumers in the repository — the deleted block and its own test — and it
is a **seeded** pattern, which is precisely what DD-93 rules out (*"lego is default, of touching sides so
pieces combined form total 3x3x3 cube"*), so it is not a primitive the Code-pane anatomy can reuse.
Reversible in one word if he wants the function kept.
