## SEMANTIC ASSET ID
The most important architectural rule is: the asset's semantic ID survives changes to its visual model. Example: furniture.sofa.3seat.v1 — a temporary procedural sofa and a later high-fidelity GLB sofa are the same semantic asset. Do not create a second project identity when upgrading geometry.

## PRODUCTION FILE CONTRACT
assets/furniture/sofa-3seat/{model.glb, metadata.json, plan.svg, thumbnail.webp}. Recommended metadata: { "id": "furniture.sofa.3seat.v1", "label": "Sofa · 3-Seat", "packs": [2], "category": "FURNITURE", "rooms": ["LIVING"], "phaseCompatibility": ["INTERIOR_DESIGN"], "dimensionsM": { "width": 2.1, "depth": 0.86, "height": 0.9 }, "pivot": { "origin": "FLOOR_CENTER" }, "mounting": "FLOOR", "snap": ["FLOOR"], "rotation": { "axis": "Y", "allowedDegrees": [0, 90, 180, 270] }, "authority": "ILLUSTRATIVE" }

## ASSET REGISTRY
Create one central registry: `export type ArchitectAsset = { id; label; packs: number[]; category; rooms: string[]; phaseCompatibility: string[]; modelUrl; planSymbolUrl?; thumbnailUrl?; dimensionsM {width, depth, height}; mounting: "FLOOR"|"WALL"|"CEILING"|"SURFACE"|"BUILT_IN"; snap: string[]; rotation: { axis: "Y"; allowedDegrees?; freeRotation? }; authority: "ILLUSTRATIVE"|"REFERENCE"|"CANONICAL" }`. Every Architect-2525 surface should reference this registry. Do not maintain separate asset definitions for PLAN, WALK and 3D.

## ASSET CARD
Each item shows: thumbnail; label; category; compatible room; 3D-ready state; placement type. e.g. SOFA · 3-SEAT / Furniture / Living Room / Floor Mounted / [ PLACE ]. Selecting the asset should open a preview or immediately enter placement mode.

## PLACEMENT MODE
The viewer proves ROTATE · MOVE X · MOVE Z. Architect-2525 extends to SELECT · PLACE · MOVE · ROTATE · SNAP · REMOVE. `type PlacedAsset = { instanceId; assetId; roomId; positionM {x,y,z}; rotationDeg; authority: "ILLUSTRATIVE" }`. Do not store the actual GLB inside project state. Store the semantic asset ID and transform.

## LOAD THE MODEL · MODEL CACHE
Recommended Three.js flow: `const gltf = await gltfLoader.loadAsync(asset.modelUrl); const instance = gltf.scene.clone(true); scene.add(instance);` Cache the original model; repeated sofas clone the cached model rather than reload the GLB. assetId ↓ GLB CACHE ↓ INSTANCE 1 · 2 · 3. Matters for chairs, framing, lights, windows, pavers, plants, repeated equipment.

## ROTATION · PIVOT STANDARD · SNAP SYSTEM
User inspection: camera orbits freely. Asset placement: asset rotates around the vertical axis (`object.rotation.y = degToRad(rotationDeg)`); most architectural objects default to 0/90/180/270; freestanding furniture may support finer increments. Pivot FLOOR_CENTER where applicable (a sofa rotates around its own footprint); wall/ceiling assets use explicitly defined mounting pivots; no per-room correction hacks. Snap targets: FLOOR · WALL · WALL_BACK · WALL_CORNER · WALL_OPENING · CEILING · SURFACE · COUNTERTOP · CABINET_UNDERSIDE · ROOF_LINE · ROOF_EDGE (SOFA → FLOOR · TOILET → FLOOR + WALL_BACK · WINDOW → WALL_OPENING · UPPER CABINET → WALL · PENDANT → CEILING).

## PACKS 1–10 · DUPLICATE NORMALIZATION · REFERENCE BOARDS · VISUAL LANGUAGE
Preserve the ten-pack organization (1 Shell & Structure · 2 Interiors & Fixtures · 3 Finishes, Lighting & Site · 4 Appliances, Utilities & Life Systems · 5 Smart Home & Automation · 6 Site & Landscape · 7 Accessibility & Inclusion · 8 Sustainability & Resilience · 9 Lifestyle & Personalization · 10 Operations & Maintenance); one asset may appear through multiple filters without duplication (appliance.refrigerator.v1 with packs [2,4], rooms [KITCHEN]). ## PROCEDURAL MODELS → GLB MIGRATION
The standalone HTML contains interactive procedural geometry for the full catalog — GEOMETRY PROTOTYPES, not necessarily final production GLBs. PROCEDURAL MODEL ↓ VISUAL QA ↓ EXPORT / REBUILD GLB ↓ PRESERVE ASSET ID ↓ REGISTER GLB ↓ TEST PLACEMENT ↓ REPLACE PROCEDURAL RUNTIME. Do not block integration while waiting for perfect final models.

## PLAN MODE · WALK MODE · PHASE FILTERING · CANONICAL TRUTH
Each asset exposes a lightweight PLAN symbol (SVG footprint); PLAN does not render detailed GLBs. Once placed, the asset appears in Walk — the same semantic instance (e.g. living-sofa-001 resolves consistently in PLAN · 3D · WALK; Walk never generates a separate sofa). Phase is a projection from the registry (Framing shows studs/trusses/rough openings and hides sofa/rug/art; Electrical shows panel/outlets/switches; Interior Design shows furniture/fixtures/cabinetry/décor); placement never modifies the phase architecture. Placed furniture/décor remain ILLUSTRATIVE; placing a chair must not alter project hash, canonical 900 ft², R-CORE revision, Project Cost, Budget Target, portfolio stage.
