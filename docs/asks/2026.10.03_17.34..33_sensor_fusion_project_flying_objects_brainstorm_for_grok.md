## 1. The project in one paragraph
**Flying Objects** is the first community project: many people collect pictures of birds and planes in the sky, label them with
two-person review, and the set becomes a new model folder of the same shape —
`PreLoadedModels/FlyingObjects.01/Sample_TFLite_model/{detect.tflite, edgetpu.tflite, labelmap.txt}`. Uses: bird watching and
citizen science, school classes, airport and plane spotting, wildlife counts. It starts with a head start: the Demo.90 model already
knows **bird** and **airplane**, so it can pre-draw boxes from day one and people correct them.

## 2. Classes — start small, grow in layers (the patent's method)
| Layer | Labels | Who adds them |
|---|---|---|
| 1 (now) | `bird`, `airplane` | pre-drawn by Demo.90, confirmed by people |
| 2 (later) | bird groups (raptor, gull, duck/goose, small songbird); aircraft kinds (airliner, small prop, helicopter, glider, balloon) | added to the set's `labelmap.txt` when enough pictures exist (e.g. 200 per name) |
| 3 (later) | species / aircraft type | experts as Level 2 reviewers |
A layer-2 model runs only inside a layer-1 box (bird → which bird), the same way Head runs inside Person.

## 3. Three ways in — all land in the same set with never-repeat names (`bird.1001.jpg` …)
**A. Upload pictures** — from the phone library or Files, several at once (the 17.14 note's "From this device").

**B. Upload a video → the fewest pictures that are different enough.** A 60-second clip at 30 fps is 1,800 frames; most are near
copies. Keep only frames that add something:
1. **Look at a few frames per second** (e.g. 4 per second), not all 30.
2. **Drop blurry frames** (a sharpness score below a threshold — flying objects blur often).
3. **Drop near-copies:** compare each frame with the last kept one using a small picture fingerprint (perceptual hash) and a
   similarity score; keep it only if it is different enough (e.g. hash distance ≥ 10 of 64, or similarity below 0.9).
4. **Prefer frames with a bird or plane in them:** run Demo.90 on each candidate; keep frames where it sees one (any score), and a
   few empty sky frames as "nothing here" examples (about 1 in 10).
5. **Cap per clip** (e.g. at most 40 pictures per minute) so one long video does not swamp the set.
6. **Show the result before saving:** "1,800 frames → 31 different pictures (12 dropped as blurry, 1,757 as near-copies)", with the
   strip of the 31, and the person can drop more or add one back.
7. The same steps run in the page (for short clips) and in the Python program (for long clips on a PC or Pi). Same rules, same
   numbers, so both give the same picks for the same video.

**C. Live video → pictures in real time** — the original Sensor Fusion **Capture Images** (Pi `TFLite_detection_webcam_api.py`:
frames to `Pictures/<name>/` with a counter), with the same "different enough" filter switched on, so pointing the camera at an empty
sky for a minute does not save 1,800 copies. Optional trigger: save only while Demo.90 sees a bird or a plane.

## 4. Many contributors, one clean set
1. **Each contributor's pictures carry who, when and source** (sensor / device / video + clip name) in their XML.
2. **Duplicates across people:** the same fingerprint check runs when sets are merged; a near-copy of an existing picture is flagged,
   not added twice.
3. **Never-repeat names across people:** renumber at merge (method c of the 17.09 note); the change is recorded in each XML.
4. **Two-person review:** Level 1 annotation, Level 2 reviewed by a different person; only Level 2 boxes train the model.
5. **A fair test set:** keep 10–20% of pictures aside for testing, split **by contributor and by clip**, so the model is tested on
   skies it has never seen — not on the next frame of the same video.
6. **Balance:** show the counts per label and per contributor; ask for more of what is missing (e.g. "planes at dusk", "birds close up").

## 5. Privacy and fairness
- Skies, not people: if a frame has a person in it (Demo.90 sees "person"), flag it; the contributor decides to crop or drop it.
- Location in photo files (GPS in the picture's metadata) is removed by default; a contributor can choose to share a rough place
  for wildlife counts.
- Contributors keep credit: the model's release notes list the contributors and their picture counts.

## 6. From set to model to live (the six-step strip of the 17.18 note)
Capture → Annotate (Level 1) → Review (Level 2) → Upload the set → Develop the model (who trains: the operator's decision) →
Download `FlyingObjects.01` (the same three files) → Run Live on phone, PC or Pi. Each release gets its revision number and the
counts it was trained on.

## 7. EdTech
- A class can run a "sky week": every student uploads one short video; the filter turns it into a handful of pictures; students label,
  partners review; the class sees its own model improve between versions.
- Simple scores to show: pictures added, boxes reviewed, agreement rate, model score on the test set.
