## The operator's words (verbatim)
> check for similar label's (ensuring consistency), and have level 1 annotation and level 2 (reviewed by)

## A. One name for one thing — catch similar labels before they are saved
Today the name box is free text (`labelName`, default `deer`), so "Head", "head ", "heads" and "hed" become four classes.

1. **The model's `labelmap.txt` is the master list.** The name picker offers its names first, in file order. The set keeps its own
   copy (`Pictures/<Set>/labelmap.txt`); a new name is added there only on purpose, never by a typo.
2. **Clean every typed name the same way** before comparing or saving: trim, collapse spaces, lower case, one form for plurals
   ("heads" → "head"), `_` and `-` read as a space.
3. **"Did you mean …?"** If a typed name is close to an existing one (same cleaned form, or one or two letters apart, or one is the
   start of the other), show the existing name first: *"Use 'head' (12 boxes) or keep 'hed' as a new name?"* One tap keeps the list
   consistent; keeping the new name needs a second tap.
4. **A small synonym table per set** (e.g. "manta" = "manta ray"), editable by the Level 2 reviewer, so two right words map to one class.
5. **A set check before Save set:** list every name with its box count; flag names used once, names that differ only by case or one
   letter, and names not in `labelmap.txt`. Merge with one tap (all boxes renamed, recorded in the XML history).
6. **Similar boxes too:** on the same picture, two boxes of the same name that overlap almost fully (IoU ≥ 0.9) are flagged as a
   likely double; two different names on almost the same box are flagged as a disagreement for Level 2.

## B. Two levels on every box
| Level | Who | What they do | What the box reads |
|---|---|---|---|
| **Level 1 — Annotation** | the labeler | draws the box, picks the name, saves | `L1 · labeled by <name> · <time>` (amber outline) |
| **Level 2 — Reviewed by** | a second, different person | Accept · Fix · Reject each box; may merge names | `L2 · reviewed by <name> · <time>` (green outline when accepted) |

1. **In the XML (Pascal VOC, labelImg still opens it):** each `<object>` keeps its normal fields and adds, after them, `level` (1 or 2),
   `labeled_by`, `labeled_at`, `reviewed_by`, `reviewed_at`, `review` (accepted / fixed / rejected) and, for a fix, the box before the fix.
   Time stamps in the app's form `YYYY.MM.DD_HH.MM..SS` (CST).
2. **Level 2 is a different person.** The reviewer's name must differ from the labeler's; two guests count as one person and cannot
   make Level 2.
3. **Only Level 2 boxes train the next model.** Save set writes all boxes; the training export (the next model folder) takes only
   `level 2, accepted or fixed`. Rejected boxes stay in the file with the reason, so the record is complete.
4. **The screen says which level it is.** Open set shows a count per picture — *"3 boxes · 2 reviewed · 1 waiting"* — and a filter
   "waiting for review" so the reviewer goes straight to Level 1 boxes.
5. **Agreement you can see.** Per set: how many Level 1 boxes were accepted as they were, fixed, or rejected, and which names were
   merged. A low acceptance rate for one name points to a confusing label, not a careless person.
6. **The same steps for pose keypoints:** Level 1 places or corrects the points; Level 2 accepts the pose.
