## Rules that do not change
- A model is one folder with three files: `detect.tflite`, `edgetpu.tflite`, `labelmap.txt`. Never rename them. Never add a second way to store a model.
- One model list, read by the page, `cnn.js` and `sensor_fusion_edge.py` (today it is typed three times).
- Nothing a person sees names a database, an error code or a vendor. One plain sentence; the detail goes to the console.
- The screen never says "saved", "uploaded" or "reviewed" before it is true.

## What to build, in order
**1. Capture Images (the green button, renamed back from "Annotate").** Three sources, one set:
- *From the sensor:* name + how many (default 4); the name is picked from the open model's `labelmap.txt`.
- *From this device:* choose photos or files, several at once.
- *From a video:* keep the fewest frames that are different enough — look at ~4 frames/s, drop blurry frames, drop near-copies
  (picture fingerprint), prefer frames where the model sees the object, keep ~1 in 10 empty frames, cap ~40 per minute; show
  "1,800 frames → 31 pictures" before saving. The same rules in the page and in Python.

**2. Names that never collide.** Form: `<label>_<NNNN>.jpg` + `<label>_<NNNN>.xml` (`bird_0001`, 4+ digits). Alone: next number =
highest used + 1, never reused. In a group project: temporary names while collecting; at **Close upload** the project numbers
everything once — members in join order, each member's pictures in capture order, one unbroken block each
(`bird_0001`–`bird_1111`, then `bird_1112`–`bird_2222`). The XML records every rename.

**3. Annotate Images (its own button).** Opens the set.
- Four edge grips (left/right move sideways only, top/bottom up and down only), placed **outside** the box so a finger never covers the
  line; thin high-contrast line; a magnifier while dragging; one-pixel nudge buttons.
- Boxes kept in picture pixels (no rounding to whole percent).
- SAVE BOX writes to the device only — no download per press.
- Names from `labelmap.txt` with "did you mean …?" for close spellings; a set check flags near-duplicate names and near-duplicate boxes.

**4. Level 1 and Level 2.** Each box in the XML (Pascal VOC, still opens in labelImg) carries `level`, `labeled_by`, `labeled_at`, and after
review `reviewed_by`, `reviewed_at`, `review`. The reviewer is never the labeler. Only Level 2 accepted/fixed boxes train a model.

**5. Group projects.** Owner, contributor, reviewer, viewer roles; invite by code or QR (reuse `inviteCode` / `admits` in
`lib/drone-2525/si-pod.ts`); sign-in required. Phases shown on a step strip: Collect → Close upload → Level 1 → Level 2 → Export.
Level 1 and Level 2 each have a queue that holds a picture for one person at a time.

**6. Save set and upload.** Save set writes `Pictures/<Set>/` (desktop folder or one zip on a phone) with every jpg+xml pair and
`labelmap.txt`. Upload sends that zip with a short manifest. Where it goes is the operator's decision. Projects are private to members.

**7. On screen.** Bring back the AI Accuracy Meter (left edge, green to red, independent of the % toggle). Use the six original training
icons (Capture Video, Add Annotations, Upload Images, Develop Models, Download ML Files, Run Live). Everything fits at 390 px.

**8. Contribution time — counted the way the eXeL AI session and the Innovation POD already count it.** Reuse
`frontend/lib/pod-clock.ts` (the pod's platform clock: start/stop events, `measure()`, `witnessedMinutes()`, `hhmmss()`), the same
clock `app/soi-session/page.tsx` and the Drone-2525 SI panel use. Do not write a second clock.
- **What counts:** every working stretch on a project element, long term — capture images (sensor, device, video), Level 1
  annotation, Level 2 review, merging names, set checks, and later project elements as they are added.
- **Clocked, not claimed.** The platform records start and stop (who, project, element, device, time); the clock's own rule holds:
  time already recorded is never lost or altered, and a claim may never exceed what the platform witnessed. Idle time closes a
  stretch. A stretch is linked to the work it produced (pictures, boxes, reviews).
- **Global time:** stored in UTC, shown in the person's own time and in `YYYY.MM.DD_HH.MM..SS` in the record; the order of events
  follows the clock's `seq`, not each phone's wall clock.
- **Shown as ♡ (SI) now:** one minute given = one ♡ (the clock's `unit.heart`). Team and member time per project, split by element;
  each model version credits members with their time and counts; a teacher view for classes, never a race.
- **Later, paid projects → 웃 (HI), the operator's decision:** from the date a project is marked paid, its witnessed hours can be valued
  as 웃 under the app's existing rule (minted only for time clocked by the platform, worked and reviewed in a pod, M × hours). ♡ itself
  is never spent or traded (decision D12); what carries over is the witnessed hours record, so either choice stays possible.

## Tests that must pass (put them in `frontend/tests/sensor-fusion-labeler.test.mjs`, in `test:ci`)
1. `readVoc(vocXml(x))` returns `x`; names like `ray & fin` survive; labelImg reads the file.
2. A saved box equals the on-screen box within 1 picture pixel.
3. Five SAVE BOX presses make 0 downloads; Save set makes 1.
4. Two members' 1,111 pictures become `bird_0001`–`bird_1111` and `bird_1112`–`bird_2222` after Close.
5. A reviewer is never shown their own box; a guest cannot join a group project.
6. A 60 s clip gives ≤ 40 pictures with no near-copies, and the same picks in the page and in Python.
7. The three model lists match the folders; the name picker shows only the open model's names.
8. At 390 px the bottom bar, header and meter are fully visible.
9. Ten minutes of Level 1 work record one stretch (member, project, element, device, UTC); idle time is not counted; a claim larger than the witnessed time is refused.
10. Team ♡ time equals the sum of members, split by capture / Level 1 / Level 2, and reads the same in two time zones.
