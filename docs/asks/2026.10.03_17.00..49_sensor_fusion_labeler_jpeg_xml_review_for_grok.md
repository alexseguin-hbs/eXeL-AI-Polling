## A. Save the picture and its XML as one pair
1. **One base name per picture**, set when it enters the labeler: `<Set>_0001`. The picture is saved as `<Set>_0001.jpg` and the labels
   as `<Set>_0001.xml` — same base name, so any tool pairs them.
2. **The XML is Pascal VOC** — what labelImg reads and writes. `<filename>` holds `<Set>_0001.jpg`; `<size>` holds the picture's real width
   and height; each box is `<object><name>…</name><bndbox><xmin>…` in **picture pixels**, converted from the on-screen box with the
   picture's natural size (keep corners inside the picture; xmin < xmax, ymin < ymax; escape `& < >` in names).
3. **One box or many**: each saved box is one `<object>`. Show the saved boxes under the picture with a delete for each.
4. **SAVE BOX stops downloading.** It adds the box to the picture's XML on the device. One **Save set** button writes the whole set:
   a folder `Pictures/<Set>/` (desktop) or one `<Set>.zip` (phone → Files) holding every `.jpg` + `.xml` pair and the model's
   `labelmap.txt`. The screen says "saved" only after that file exists.
5. **The name comes from the open model's label list** (a dropdown from `labelmap.txt`), preset to what the model sees in the box.
   Typing a new name adds it to the set's own copy of the list. No silent `deer` default.

## B. A teammate reviews it later
1. **Open set**: the labeler gets a button that opens a saved `<Set>.zip` or folder and shows each picture with its boxes, read back from
   the XML (the same reader both ways, so what was saved is what is shown).
2. **Accept · Fix · Reject** per box. A fix moves the edges with the same tools as section C.
3. **Who and when go in the file.** The XML carries `labeled_by`, `labeled_at`, `reviewed_by`, `reviewed_at`, `review` (accepted / fixed /
   rejected) as extra elements **outside** `<object>`, so labelImg still opens it. Time stamps in the app's form `YYYY.MM.DD_HH.MM..SS`.
4. **Two people.** The reviewer must not be the labeler (different names; "GUEST" twice is one person). Only accepted pictures go into
   the training folder.
5. **Sharing through the cloud is the operator's decision.** If used, the picture and its XML travel together under the same base name,
   and the reviewers found the current shared pictures are readable by anyone — pictures of people should not be public by default.

## C. Edges you can see while you drag — the line as close to the true edge as possible
1. **Four edge handles, each on one axis.** A grip on the left line moves only the left line, left–right. Same for the right line.
   A grip on the top line moves only the top, up–down; same for the bottom. Keep the two corner handles for moving two edges at once.
2. **The grip sits outside the box, off the line.** Put each edge grip a finger's width outside the line (left grip to the left of the
   left line, top grip above the top line), joined to the line by a short tick. The finger then covers the grip, never the line.
3. **A thin line and a wide touch zone.** Draw the line 1 px in high-contrast green with a thin dark outline so it shows on light and
   dark pictures. Make the invisible touch zone at least 44 px wide, but on the outer side of the line.
4. **A magnifier while dragging.** Show a round loupe above the finger: the picture around the line at 3–4×, with the line drawn in it.
   The person places the line on the edge of the object while seeing it, not guessing under a fingertip.
5. **Fine nudge.** Tap an edge to select it, then ◀ ▶ (or ▲ ▼) buttons move it one picture pixel per tap. The four number boxes
   (Left / Top / Right / Bottom) stay and show picture pixels, not percent.
6. **Snap to the object's edge (optional, later).** A "fit" button moves each selected line to the strongest nearby change in the
   picture. The person still decides.
7. **Keep a minimum box size** and never let the left pass the right or the top pass the bottom.
