## 3. The flow he asked for: two steps, both sources, one set
```
Step 1  CAPTURE IMAGES ──┬── From the sensor (live camera): name + how many → frames saved
                         └── From this device (upload):    choose files       → copies added
                                   │  both write into the same set, same names: head.1001.jpg, head.1002.jpg …
                                   ▼
Step 2  ANNOTATE IMAGES ── opens that set (or any saved set) → boxes → Level 1 → Level 2 review
```
1. **Rename the green button back to "Capture Images"** (the original word). Tapping it asks one question: *From the sensor* or
   *From this device*.
2. **From the sensor:** the Save pictures dialog stays, with two fixes — **Name** is the label picker from the open model's
   `labelmap.txt` (required, with the "did you mean" check), and **How many** keeps its default of 4. Frames are named by the
   never-repeat rule (`head.1001.jpg` after `head.1000`).
3. **From this device:** the phone's picker (photo library or Files), several at once. Each chosen picture is copied into the set
   under the same never-repeat name; the original file name is kept inside its XML (`<source>`), so nothing about where it came
   from is lost. Very large photos are kept at full size; the box is still stored in picture pixels.
4. **One set holds both.** A set is a folder of pairs (`head.1001.jpg` + `head.1001.xml`), whatever the source. Each XML records
   `source` = sensor or device, the model that was open, and the time stamp `YYYY.MM.DD_HH.MM..SS`.
5. **Annotate Images** (its own button, after Capture) opens the current set by default, with a strip of its pictures; "Open set"
   picks another. Saving, Level 1 / Level 2 and Save set follow the labeler notes of 2026.10.03.
6. **Upload Images** keeps the original meaning — sending a finished set (one zip) for training a new custom model — not adding
   pictures. Where it goes stays the operator's decision.

## 4. Bring back the AI Accuracy Meter
1. **What it shows:** the score of the strongest box on the current frame (0–100%), as a vertical bar on the left edge of the
   picture: green at the top, through yellow, to red at the bottom; the fill rises with the score. No box → the bar is empty.
2. **Independent of the % toggle:** % on/off shows or hides the numbers on boxes; the meter stays (as in the original, two controls).
3. **Same in the Python program:** the same bar drawn on the left of the OpenCV window, from the same score.
4. **Sizes:** thin (8–12 px) so it never covers the subject; it moves with the picture in full screen and landscape.
