## What the two lines establish, read plainly

1. **SI is a consensus engine over a KEY GROUP** — not an open poll. Membership is closed and deliberate.
2. **It runs on eXeL Polling** — the engine this repository already is. SI is a new consumer of Cubes 1, 4
   and 7, not a second polling system.
3. **Its job is prioritising CRITICAL DECISIONS IN REAL TIME** — decisions that are already happening, on a
   clock, not a survey conducted afterwards.
4. **Gaming first.** The first place it runs is inside a game, which in this repository means the
   Drone-2525 round.
5. **SI is ON or OFF.** A single switch, with the OFF state being the normal one.
6. **A QR code or link goes to key members only.** Reaching the vote requires having been invited.
7. **Input is VOLUNTEER.** Nobody is obliged; a member who says nothing is not counted as anything.
8. **Contributors are rewarded in SI TOKENS** (♡ in the SoI Trinity — Shared Intent).

## Where it lands first, and why

The Drone-2525 round already contains exactly one decision that is critical and on a clock: a machine that
is aiming must ask a named person before any shot, and nothing fires while that question is open. Today one
person answers it. With SI ON, that same question is put to the key group, in the seconds it is open, and
their volunteer input is what informs it.

That is the seam. SI does not invent a decision to vote on — it takes the one the round already has.

## PLACEHOLDER — what that word means here

This edition builds the surface, the membership, the invitation, the tally and the reward record, all of it
local and deterministic. It does NOT yet create a real polling session or write a real token ledger. Every
screen that shows a number says which of the two it is, and the seam where the live engine attaches is named
in the code rather than implied.
