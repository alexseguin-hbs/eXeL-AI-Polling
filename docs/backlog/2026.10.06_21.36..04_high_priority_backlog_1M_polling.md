## Notes recorded from AsM round 2 (2026-10-07)

- **HP-07 token limits.** The participant token has no expiry and no rotation; it is bound to one session and one participant, so a leaked token is good for that session only, for as long as it runs. It lives in sessionStorage, so a new tab or a closed browser means joining again. Rotating `SESSION_SECRET` invalidates every outstanding token: rotate between sessions, never during one. The voice WebSocket carries it as a query parameter (browsers cannot set headers there), so strip it from access logs.
- **HP-11 transitional risk.** A `/api/sessions` record stored before the write key existed has no hash, and the first settings write claims it. Such records expire within the 24 h store TTL, so the window closes on its own.
- **Quadratic Borda at 1M.** Only the equal-weight tally runs in Postgres; `quadratic_borda` loads every ballot (Python path), so the 88 MB figure does not hold for it. Needs CODE (stake-weighted SQL tally) if quadratic sessions are expected at that scale.
- **Index toward HP-29.** `user_rankings` has only (session_id, cycle_id); the anomaly window sorts by submitted_at per session. An index on (session_id, cycle_id, submitted_at, id) keeps that sort cheap past 1M — to add with the 10M work.
