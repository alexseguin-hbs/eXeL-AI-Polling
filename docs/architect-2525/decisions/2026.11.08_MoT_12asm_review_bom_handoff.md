## The 12 reviews (111 words each)

**Enki · systems integration** — The BOM must feed the take-off already in `architect-house-truth.ts` +
`architect-estimate.ts` (the ten $240k rows) and the Build-by-phase take-off — not a parallel `pricing/` module, which is
the "disconnected total cards" the ruling forbids. And 12/10/1 must drive quantities from ONE geometry source, yet
`room-objects.ts` uses a 10-ft `ROOM_GRID` that is a different layer from the 36-ft shell. Risk: two cost systems and two
geometries. Change: name the single geometry source and the single take-off module the BOM wraps/replaces before writing
any pricing code.

**Thor · risk / failure** — 30→36 ft is a canonical-geometry change, not a label fix. The immutable seed
`tiny-home-v1.ts` is a 10-ft clear grid (30×30); the canonical-schema gate and R-CORE replay are pinned to it. Flipping to
12-ft outer modules can invalidate stored user designs, break the `architect-canonical-*` tests, and shift hashes
mid-flight. Risk: saved projects orphan on load. Change: Round 1 adds an explicit migration + WireGuard (re-seat untouched
projects, keep arranged ones), a geometry-contradiction gate, and a full `architect-canonical-*` run before ship.

**Odin · replay / continuity** — History is immutable; estimates must replay. The BOM adds a price-book revision as a NEW
time axis; if design-rev and price-rev aren't both in the record, replay can't reproduce an old total. Risk: an old
estimate becomes unreconstructable. Change: before coding, every estimate record carries both `design_revision` and
`price_book_revision`, and a replay test proves an old (design, price-book) pair reproduces its exact historical total.
The $240k baseline and prior revisions must still reconstruct unchanged.

**Athena · logic / contradiction** — Two clauses collide: "restore the ten $240k rows" vs "BOM is truth; don't force the
total to $240k." If both render as current cost, the two-totals bug returns. And "one phase identity per element" presumes
one enum, but the repo has Build-by-phase order, construction phases, and Vision-Tree groups — three vocabularies. Change:
$240k is REFERENCE-only once BOM coverage passes a threshold; require a phase-enum audit (enumerate every existing
identifier) with one canonical mapping before any tree/BOM/health wiring.

**Krishna · human interaction** — Room density is the live pain: `defaultObjectsForRoom` packs items top-left. The ruling
wants REQUIRED / PLACED / RECOMMENDED / LIBRARY distinct and curated defaults with all 139 reachable. Risk: if RECOMMENDED
and PLACED both draw on the plan, the user can't tell what's real — an explicit acceptance FAIL. Change: RECOMMENDED is a
suggestion state that is NOT a placed instance (no `ASSET_PLACED` event) and renders distinctly; the per-room default is
the curated `DECOR_DEFAULTS` set, expert-placed via `STANDARD_LAYOUTS`, never the bin-packer.

**Enlil · determinism** — BOM quantities and roll-ups must be pure functions of (geometry, method, price-book) — replay
law, no `Math.random`/`Date.now()` in canonical values; the packer already honors this. Risk: a price "refresh" that reads
wall-clock or live network prices is non-deterministic and unreplayable. Change: the price book is a dated, versioned data
file (pure input), never a live fetch inside canonical calc; recalculation is a deterministic pass; gate "same inputs →
same total."

**Sofia · language / accessibility** — The `architect-voice` gate bans machine words on the human path. "BOM",
"evidence_state", "source_type", "calculation_version" are machine words; even the human example softens to "BOM-derived ·
97% priced." Risk: cost UX leaks schema jargon to the homeowner, failing the gate and the "signer never meets the machine"
law. Change: the human cost view speaks plainly ("what it takes to build", "priced from today's prices", "3 items not yet
priced"); schema terms stay in Advanced/CAD + data; extend the voice gate to the new cost surface.

**Aset · evidence / provenance** — The model's strength is evidence labels + a source hierarchy (QUOTE > CONTRACT >
PRICE_BOOK > MARKET > USER > ASSUMED > UNPRICED). Risk: an UNPRICED line silently extends to $0, so the total reads low but
confident — the exact drift the model exists to prevent; the $34/$35/$25 wall figures are UNVERIFIED in the repo. Change:
UNPRICED contributes null (not 0) and shows in coverage; wall benchmarks are labelled REFERENCE/UNVERIFIED (never QUOTED);
every price-book refresh writes a provenance delta (old/new/changed-lines/Δ/timestamp).

**Pangu · greenfield architecture** — The one genuinely new structure is the BOM + price-book engine. Risk: building it as
yet another parallel architecture — the Future mistake again — instead of the spine under the existing Overview/Simulate/
Build. Change: introduce the BOM as the single take-off/pricing source the existing surfaces read, replacing the manual
totals in `architect-estimate.ts` rather than sitting beside them; stage it behind the already-live displays (quantities →
pricing → recalc → UX); never a new route or tab.

**Christo · human consequence / simplicity** — The homeowner must trust the number without understanding the engine. Risk:
the full drill-down and the dual revision axes, if shown by default, bury the person in spreadsheet detail —
over-engineering that erodes trust. Change: the default cost view is ONE honest number plus coverage and price-book date;
all depth lives behind an explicit "View breakdown." Keep the first live proof about the house being coherent (36 ft, one
geometry), not about cost machinery — lead with clarity, not capability.

**Thoth · arithmetic / exactness** — Numbers check: 3×12 = 36 ft; 1,296 gross; 9×100 = 900 clear; 396 difference ✓. Ten
rows sum to 240,000; MEP = 21+18+16 = 55,000 (a derived rollup, not a source row); 240,000 ÷ 900 = 266.7 → repo rounds
$267. Risk: the BOM total will NOT equal $240k, and labor can double-count (material rows + the separate labor engine).
Change: fix the estimate equation exactly — material (Σ extended) + labor (from `architect-labor.ts`, once) + allowances —
gate that no row is counted twice; keep $240k as a labelled variance benchmark only.

**Asar · completeness / closure** — The contract is complete and the sequence is sound (Round 0 evidence → Round 1
geometry truth → BOM staged). Risk: the scope is vast (geometry + placement + BOM + phase alignment + authority); trying
to land it in one push repeats the over-reach that sank Future. Change: bind the order — ship Round 1 (one coherent 36-ft
house, all views agreeing) and the expert room placement FIRST, each reviewed by Grok/eXeL/DeepSeek, before the BOM engine
opens. "Prove improvement live" = a small true increment shipped and verified, not the whole program at once.
