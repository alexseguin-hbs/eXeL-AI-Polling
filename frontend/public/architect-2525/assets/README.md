# Architect-2525 · 3D asset library (runtime copy)

This folder is served at `/architect-2525/assets/…` and is the runtime's ONE asset library: `manifest.json` (the registry — `{library, version, assets[{id, label, category, model, metadata, planSymbol, thumbnail}]}`), `models/*.glb` (glTF 2.0 binary, **metres**, X width · Y depth · Z up, origin **floor-centre**, indexed triangles, materials with `baseColorFactor`), `metadata/*.json` (the per-asset contract — validated against `schemas/asset.schema.json`: dimensionsM, pivot, rotation, mounting, snap, authority, rooms, phaseCompatibility), `plan/*.svg` (top-down PLAN footprints) and `thumbs/*.png` (256×256 three-quarter isometric picker renders made from the same GLB). Concept + starter pack by **eXeL AI** (the operator's 3D Asset Starter Pack, `docs/architecture-2525/asset-library/3d-starter-2026-11-06/`, 18 assets, intake master `docs/asks/2026.11.07_architect2525_3d_asset_intake_master.md`). **The semantic id is law**: a placement stores `assetId` + transform, never geometry; a rebuild or a higher-fidelity replacement keeps the id, the dimensions contract, the floor-centre pivot, the mounting/snap/rotation semantics and the PLAN linkage — it replaces the file, never the id. Assets are ILLUSTRATIVE: placing one never touches canonical truth (project_hash, PLAN revisions). Generated entries (today `structure.stud.2x4.v1`) are compiled by `scripts/architect-assets-build.mjs` from `lib/architect-2525/assets/compositions/` through the pure in-repo GLB writer; the runtime reads every GLB through the pure in-repo reader (`lib/architect-2525/assets/gltf/glb-reader.ts`) into the existing SVG pinhole projector (`lib/solid-shade.ts` solidFaces) — no three.js. Gates: `npm run test:architect-asset-glb` · `npm run test:architect-asset-glb-build`.
